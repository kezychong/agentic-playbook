# Agentic Starter Kit: setup and permissions

Agentic Playbook — **by Kezy**

## Prepare a safe first run

Create a dedicated draft directory, outside live profiles and synced operational folders. Copy the blank worksheet and use the fictional example first. Choose the one skill needed for that example. Read its SKILL.md and README plus any support file it names; do not run bundled code during this review.

Copy the complete skill folder and its required companions into the skill directory documented by your chosen host. Do not copy only SKILL.md: scripts, references and templates are part of the method. If the host does not support skill discovery, use the method as a manual prompt in a sandboxed draft session. Host installation and discovery have not been tested here.

For a duplicate skill ID, compare versions and back up the existing full folder before replacing it. Merge user settings separately. Open a fresh session, ask the host which skill it loaded, and run the draft-only example. Check the output against the expected result; do not equate a discovered name with a working integration.

## Scope before access

Record the approved source folder, destination folder, accounts (if any), allowed reads, permitted draft writes and prohibited actions in the worksheet. Blank permissions mean no access. A user profile, whole drive, mailbox or chat history is not implicitly in scope. Read-only access can still disclose data; use synthetic inputs first.

Keep API credentials in the provider/host's secure local setup. Do not paste secrets into chat, notes, example configuration or generated reports. Record only credential names and whether the connection is configured. Before any external API call, review data leaving the machine, retention, permissions and possible costs with the owner.

## Approval and verification

Show the actual proposed content, recipient/destination and impact before sending, publishing, spending, deleting, installing, scheduling or changing a live profile/account. Preserve existing files and prepare a rollback. Verify the saved output or returned service state before saying an action succeeded. If an output cannot be checked, say exactly what remains unknown.

## Update or remove

Save the prior package version and the user's own configuration separately. Review changes to scope and dependencies before updating. To remove, disable any approved schedules first, revoke optional connector permissions through the provider, then remove the installed skill folders after approval. Restore profile files from the recorded backup if that was part of setup; do not delete user-created notes or project history. Removing a skill alone does not undo previous installations or account grants.
