# Project operating instructions

Use this file as the single source for project rules. Tailor every section to facts confirmed by the owner or found in the project.

## Project purpose

State the business outcome, who it serves, what success means, and any confirmed deadline or constraint.

## How to begin a work session

1. Read `STATE.md` for the current truth and next action.
2. Read `ROADMAP.md` for milestones and sequence.
3. Read `DECISIONS.md` before reopening a settled choice.
4. Read the latest entries in `LOG.md` for recent work.

## Working rules

- Verify the real project before claiming something exists, works, or is complete.
- Preserve existing work and ask before renaming, moving, merging, or reorganizing it.
- Keep new work inside the agreed project home.
- Ask when a missing fact would otherwise have to be invented.
- Make the smallest safe change that completes the approved task.

## Project boundaries

Record what is in scope, what is deliberately outside scope, and which actions require the owner's approval.

## Memory update rule

After work changes the project:

1. Append what changed and how it was checked to `LOG.md`.
2. Refresh `STATE.md` so it reflects the current truth.
3. Update `ROADMAP.md` when a milestone moves.
4. Record meaningful choices in `DECISIONS.md`.

## Definition of done

Describe the evidence required before work can be called complete. A plan, draft, or status claim is not proof of a finished result.
