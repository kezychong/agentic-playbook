# Failure lessons preserved as generic mechanisms
This is a rebuilt operational playbook. It contains no private session history or performance promises.

- Conflicting old routing notes can revive retired models. Resolve conflicts against the lane's current pairings.
- Thinking agents are allowed to run in parallel. The restriction is resource capacity, not a ban on capable reviewers.
- Too many overlapping fleets can consume the shared allowance at the final merge. Use waves and save between them.
- A confident worker can report files that were never written. Inspect real artifacts and use an independent reviewer.
- A reviewer sharing the builder's conversation can inherit its assumptions. Give fresh reviewers only bounded inputs.
- A model setting without an effort setting can launch the wrong work level. Verify both in execution receipts.
- A background process can wait forever for more input. Close its input and use a scoped deadline.
- Missing run identifiers turn recovery into repeated work. Persist identifiers and use supported journal replay.
- A failed tracker does not prove a dead process. Check the actual job before retrying.
- Separate execution providers can reduce contention on one allowance. Check actual billing and account routing.
- Advisor access varies by provider. Preserve escalation when the advisory mechanism is absent.
