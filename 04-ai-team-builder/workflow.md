# From recurring work to a useful AI team

Agentic Playbook — by Kezy

1. Write one concrete outcome and list approved inputs. If it is a one-off, finish the task without
   creating a persistent profile. For a proven repeatable task use [Learn Skill](learn-skill/skills/ap-learn-skill/SKILL.md).
2. For recurring responsibilities use [Hire an Agent](hire-an-agent/skills/ap-hire-an-agent/SKILL.md): apply the
   split rule, define one job, expected weekly output, exact read permissions and non-overlap.
   Interview in small batches. Stage identity, manual, workspace and memory templates. Preview
   before live installation; no auto-created runtime or blanket access.
3. For a multi-part job select [the primary lane](orchestrator-astra/skills/ap-orchestrator-astra/SKILL.md) or
   [the alternate lane](orchestrator-opus/skills/ap-orchestrator-opus/SKILL.md). Verify actual available models,
   effort support and budget. Write the plan first; give workers disjoint ownership and a deadline.
   Preserve the source method: delegate bounded builds, escalate judgment, save resume state,
   run mechanical checks, then obtain a fresh-context review. A fallback is disclosed.
4. Review a finished artifact with [Fresh Eyes Judge](fresh-eyes-judge/skills/ap-fresh-eyes-judge/SKILL.md).
   Supply only the brief, artifact, criteria and named check receipts. Evidence, not confidence,
   determines PASS, NEEDS_REPAIR or FAIL. Same-agent review is not independent.
5. After real use, [Skill Levelup](skill-levelup/skills/ap-skill-levelup/SKILL.md) traces a run, ranks changes
   against speed, cost and quality, and applies approved changes with before/after evidence.

A new hire stays on probation for three approved drafts. Scheduling, provider charges and profile
activation need separate approval. If the host has no delegation tool, deliver the plan and mark
execution unperformed. No runtime was tested here.

## Update and removal
Keep a versioned copy of a working skill before replacing it. Review changed access and behavior.
Pause any separately configured schedules first; remove only the selected skill/profile after
approval. Revoke integrations separately. Keep or delete work records according to the owner's
retention decision, never as an automatic side effect of removing a skill.
