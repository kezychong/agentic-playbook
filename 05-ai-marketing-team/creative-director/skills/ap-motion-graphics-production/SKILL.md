## Use boundary and runtime status

Agentic Playbook — **by Kezy**. This is an original public workflow built from common motion-design practices. It contains no private projects, brand files, paid-service setup or copied renderer instructions.

These are uninstalled source assets. No renderer, package, browser capture, media generator, cloud service or host integration was tested. Loading this skill starts nothing. Do not install, make paid calls, upload, publish, send, delete or change a live system without a separate exact approval. Use permitted assets only, keep credentials out of source and stop at a local review draft.

# Motion Graphics Production

Use for designed movement, diagrams, interface animation, data-driven scenes, title sequences or a programmatic visual system. For simple cuts around a real speaker, use Short Video Production. For narration-led teaching, pair this with Narrated Video Production.

## Inputs

Require an approved canvas, exact claims, brand rules, output dimensions, frame rate, duration range, permitted assets, rights status, accessibility needs, local output folder and reviewers. Missing brand rules become explicit design decisions; do not guess that a private brand file exists.

## Workflow

### 1. Choose the production route

First inspect any existing approved project. Preserve its toolchain and structure unless a change is justified. For a new project, compare practical routes against:

- local availability and licence;
- deterministic rendering;
- support for the required animation and media;
- editability after handoff;
- offline operation and privacy;
- render time and failure recovery;
- cost and external service use.

If the decision matters, propose a short local prototype in no more than two routes. Do not install both merely to compare them. A cloud renderer or generated-media service is a paid or external action and needs separate approval.

### 2. Write the truth block

Create one compact block containing the only approved names, facts, numbers, dates and claims. Each item points to source IDs. The animation may restate these items but may not introduce a stronger claim.

### 3. Build a timed storyboard

For each beat, record start, end, message, visual action, source IDs, asset, accessibility note and transition. Motion must help the viewer understand change, sequence, scale, relationship or emphasis. Decorative movement is optional and must not compete with the message.

### 4. Prepare assets

Inventory fonts, logos, screenshots, icons, sound and media. Record owner, licence and allowed use. Copy only approved working assets into the project. Do not fetch fonts, music or stock automatically. Do not use private account views or hidden interface data as visual texture.

Generated images or clips must be clearly tracked as illustrative. Never use them as proof of a real person, product result, event or interface state.

### 5. Build in small proofs

Create the smallest representative scene first. Check type size, safe frame, colour contrast, movement, render path and editability before building the full timeline. If the proof needs a package install, paid call or external upload, stop and request approval with scope and estimated cost.

### 6. Render locally when available

Use the approved project command and pinned local versions. Record the command, version, duration and output. Preserve the source and exact configuration. Long renders need a recoverable log and a resumable plan; a partial render is not a finished file.

### 7. Judge the actual render

Review frames from the rendered video, not only source code or a design preview. Sample every major reveal, transition and data change. Then watch the full file with sound.

Check:

- truth block matches the visible copy and narration;
- each major beat appears at the intended time;
- no text clips, overflows or leaves the safe frame;
- contrast holds inside nested cards and overlays;
- screenshots and evidence remain readable;
- charts retain labels and do not exaggerate scale;
- motion settles long enough to read;
- no false buttons or clickable-looking controls appear in a passive video unless showing a real interface;
- audio is present, intentional and licensed;
- final dimensions, frame rate, duration and streams match the brief.

A still sampled during a transition may look incomplete. Check a settled frame before calling it a defect.

### 8. Produce the review handoff

Deliver the local render, editable project, storyboard, truth block, asset ledger, render facts, sampled-frame review, known limits and exact reviewer decision. Mark it review-ready, not published.

## Failure rules

- If a renderer or required package is unavailable, stop at a complete brief and report the missing prerequisite.
- If a paid service is declined, use an already available local route or remove the affected beat; do not silently spend.
- If rights are unclear, replace the asset with an original shape, text treatment or blank hold.
- If a final render differs outside the requested revision window, preserve the last approved draft and investigate the drift.
- If a check was not run, say so. Source validity is not render validity.

## Hard boundary

This skill never publishes, uploads, sends, buys media or calls a paid service by default. It does not train, clone or imitate a person's voice or face. Any separately approved synthetic-media work belongs in another rights-reviewed workflow and is outside this package.
