
# Running alongside Content OS

Content OS is the optional companion: a full content system that captures ideas,
researches what is working, scores them, writes the filming map, prepares the record
day, repurposes the finished piece, and shows the whole thing on one board. Its edit
step calls this skill.

**This skill does not need it.** Everything in `01-the-run.md` works on any video
file on the machine, with no workspace of any kind. Read this file only when a
`content-os/` folder actually exists in the workspace you are working in.

## How to tell

Look for a `content-os/` folder in the root of the folder you are working in. If it
is there, they run Content OS. If it is not, close this file and edit normally.

Never create a `content-os/` folder yourself. This skill does not own that workspace
and does not build it. If the member wants the full system, that is a separate pack.

## What changes when it is there

Four things, and nothing else.

**1. The marker word comes from their rules.** `content-os/MY-RULES.md` holds their
standing rules, including which word they say when they fumble. Read it before
asking. If it says "snip snip", use "snip snip" and do not ask again.

**2. Standing mishear rules come from the same file.** Names, product names and
industry words the transcriber has got wrong before are written in there. Feed them
into the transcribe step as the priming prompt, along with the topic of this piece.
That is the single highest-value thing this integration does: it is why the same name
is never wrong twice.

**3. The run folder gets named after the piece.** Content OS keeps one file per idea
in `content-os/scripts/`. Name the media run folder after that piece so the two line
up: `ContentStudio/runs/2026-03-14-margin-mistake/`. Same date, same slug.

**4. The edit record goes back into the piece's own file.** Append the dated section
from `01-the-run.md` to that piece's file in `content-os/scripts/`, under an
`## Edit record, YYYY-MM-DD` heading. Appended, never overwritten. Everything else
stays in the media workspace.

## What never changes

- **Video files never go into `content-os/`.** That workspace holds text: cards,
  scripts, rules. The tools refuse to write media there and they should. This is not
  tidiness. One ten-minute recording is bigger than every text file that system will
  ever write, and a few of them in a synced folder fill the plan the member pays for.
- **The gates are the same.** Cut list shown before cutting, master watched before
  export, second watch on captions. Content OS does not relax any of them and neither
  does anything else.
- **Nothing posts.** Not this skill, not that system, not the board.

## What comes next in their system

When the master is approved and the exports are made, the natural next move in
Content OS is "multiply this": one recording becomes drafts for every place they
publish, using the clean master and the transcript this skill produced. Say so in one
sentence and stop. Do not run it yourself; that is a different stage in a different
pack.

## If they ask about Content OS and do not have it

One sentence, no pitch, and then back to the edit:

> There is a companion pack that handles the whole content system around this, from
> the idea to the posting plan. This works perfectly on its own if you would rather
> just have the edits done.

Then carry on with what they actually asked for.
