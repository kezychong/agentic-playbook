# Start here

**Agentic Playbook — by Kezy**

## Choose one useful result

You do not need to install the whole collection.

- **New to AI skills:** begin with [Agentic Starter Kit](01-agentic-starter-kit/README.md).
- **Too many scattered notes:** use [The 2nd Brain](02-the-2nd-brain/README.md).
- **Want a personal assistant:** follow [JARVIS Setup](03-jarvis-setup/README.md).
- **Want specialist agents:** begin with [AI Team Builder](04-ai-team-builder/README.md), then pick [Marketing](05-ai-marketing-team/README.md), [Sales](06-ai-sales-team/README.md) or the [Finance Agent](07-ai-finance-team/README.md).
- **Need software or account setup:** use [Setup Guides/Tools/Connections](08-setup-guides-tools-connections/README.md).
- **Want an always-on assistant with a second brain, step by step:** follow the [Build Track](02-the-2nd-brain/TRACK.md).
- **Want an optional review of new code:** read [AI Security Team](09-ai-security-team/GUIDE.md) before installing Code Security Auditor or approving an audit.

## Your first run

1. Pick a topic and one skill that solves a real task.
2. Read its human README and requirements. A skill may need supporting files, another skill, software or a separately approved account connection.
3. Use the guide for your AI host. Copy a complete skill folder, not only SKILL.md. Never replace existing personal settings or edited skills blindly.
4. Confirm the host can find the named skill.
5. Try the supplied fictional example first. Ask for a draft, not an external action.
6. Compare the result with the expected output. Check factual support, missing information and approval boundaries.
7. Only then decide whether to use real data. Check what the chosen AI service receives and retains.

## Keep private working data separate

Do not put passwords, customer details, financial records, chats or your completed onboarding answers inside this public project. Copy blank templates into a separate private workspace before filling them in. Never paste a password or access key into an AI chat.

Keep skill instructions separate from live settings and outputs. A published template named SOUL.md or config.yaml is only a template; it must not replace an installed assistant file without a review and your explicit approval.

## Package status

This is a source collection with runtime status untested. Setup guidance can be checked against official documentation without proving that every supplied script or live integration runs correctly. Do not treat a successful file check as a live-system test.

Use the source folders in this project. The catalog and package manifests state included skills and shared dependencies. Older separately generated archives may predate this collection's terms and additions; they are not current releases. Do not silently overwrite an existing skill with an older package version.

## Updates and removal

Record the installed skill IDs and versions. Keep personal edits outside the original package or preserve them before an update. Compare versions and changes, install only what you approve, and repeat the harmless example.

To remove a skill, remove only that skill's installed folder after checking whether another installed package uses it. Account connections and scheduled jobs are separate: disconnect or disable those explicitly in the host service rather than assuming deletion of a skill revokes access.
